# Further reading

*The running version. [Appendix E](/chapters/further-reading) is this list frozen at printing, and the landscape moves faster than a book can, so treat both as a snapshot rather than a survey.*

Missing something that belongs here? [Say so in the issue tracker](https://github.com/Left-of-the-Loop/manuscript/issues).

## Tools

- **GitHub Spec-Kit** — [github.com/github/spec-kit](https://github.com/github/spec-kit)
- **BMAD-Method** — [github.com/bmad-code-org/BMAD-METHOD](https://github.com/bmad-code-org/BMAD-METHOD)
- **AI Hero**, Matt Pocock — [aihero.dev](https://aihero.dev). Its `/grill-with-docs` skill is what makes the Spec Session executable.
- **AI Unified Process (AIUP)**, Simon Martinelli — [unifiedprocess.ai](https://unifiedprocess.ai). A whole process rather than a tool: the spec is the source of truth, and code, tests and documentation are regenerated around it. It carries a brownfield workflow for legacy systems, and open [Claude Code plugins](https://github.com/AI-Unified-Process/marketplace).

## Concept

- **"Spec-Driven Development: From Code to Contract in the Age of AI Coding Assistants"** (2026) — [arxiv.org/abs/2602.00180](https://arxiv.org/abs/2602.00180)

## Risks

- **ThoughtWorks Technology Radar, Volume 33** (2025) flags that the workflows "remain elaborate and opinionated" and that some tools "generate lengthy spec files that are hard to review."

## Closest external framing

- **Kief Morris, "Humans and Agents in Software Engineering Loops"**, in "Exploring Gen AI" at [martinfowler.com](https://martinfowler.com), on humans *on* the loop, building and maintaining the harness. Morris solves where humans sit in the process; this book solves what they need to do before it starts.
